# 平台账号与登录恢复

小红书与 BOSS 使用 OpenCLI Browser Bridge。知乎、猎聘动态页和脉脉共用 KnowledgeRadar Browser Link（KR 浏览器连接器），不挂 CDP 调试器、不再经 OpenCLI。两种连接都借用本人日常 Chrome；连接在线不等于站点已登录。无需搬 Cookie、建立账号池或维护 BOSS 专用浏览器。

## 日常使用

- KR 浏览器连接器是可选安装组件：在官方商店确认安装权限后，扩展自动连接本机 Host，浏览器重启、扩展更新和普通断线均自动恢复，不再要求点击“连接此浏览器”。同一 Profile 身份持续复用，冲突时停止并说明原因，不覆盖另一个浏览器的绑定。Host 随 KR 安装器部署，仅向当前 Windows 用户注册；普通用户不需要开发者模式或手动注册脚本。商店尚未发布时控制台明确显示等待分发，不提供虚构地址。
- 在 Chrome 登录各站点。浏览器连接器断开后退避重连通信，不重放未知站点请求、不推断为退出登录。小红书使用 OpenCLI 原生等待机制。
- 只有页面明确要求登录时，才展示该平台工作标签让用户登录；重复请求复用同一等待事件。完成后确认恢复，重新检查站点认证，继续未完成任务。
- 登录等待有期限并释放任务执行槽。未知页面、空结果和接口错误不会被当作扫码问题；安全验证立即停止，由用户处理，不自动撞验证码。
- KR 只回收自己创建的标签和会话，不关闭日常 Chrome。用户关掉 Chrome 后连接会断开，再次打开并连回同一绑定即可复用原站点登录态；站点自行过期仍需登录。

## 兜底与其他平台

小红书登录恢复失败、公开路径不可用或被安全限制时，可按已配置 TikHub 的能力使用最后兜底。TikHub单独限制每天2个实际API请求，分页和评论请求也占次数，缓存不占；不计入百炼每天10元的预算，也没有全局总预算。发送结果未知仍占次数、不自动重发。万方继续停用。各家搜索只用免费额度，详见API_KEYS。

猎聘公开职位详情优先直接 HTTP，动态部分才申请浏览器。脉脉读取当前账号可见的社区讨论和有限评论，不保证全站或全量。V2EX 使用 HTTP 或可选个人 API 令牌，提供分页继续位置并服从服务端限流；不需要浏览器连接器。账号、密钥、Profile 与任务数据留在本机数据根，更新不覆盖。

开发预览只读；日常账号恢复使用当前安装的控制台。分支源码验证不代表已更新正式安装。
